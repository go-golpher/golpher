# Tasks — Harden Production Foundations and Query

Implementation checklist for change `harden-production-foundations-and-query`.
Tasks are ordered by dependency and grouped into small, verifiable batches.
Each task names the file(s)/module in scope and an observable completion
criterion where it reduces ambiguity. Tests (regression + contract) sit
**beside** each batch, not only at the end.

Conventions:
- Behavior tests that require package internals may remain in `package golpher`.
  Add a separate `public_api_test.go` in external package `golpher_test` for
  consumer-visible API contracts; do not force unrelated existing tests to move.
- Per-batch validation: `gofmt` only on changed Go files, `go test ./...`,
  `go test -race -shuffle=on ./...`, `go vet ./...`, `go build ./...`,
  `go mod verify`; run `golangci-lint` if available. After every batch also
  run `openspec validate harden-production-foundations-and-query --strict`
  and inspect `git status` / `git diff --stat`.
- No version bump, dependency changes, Go upgrade, multi-source binding,
  or features outside this change.

## 1. App construction: private config/router/error, lifecycle mutex + freeze flag

- [x] 1.1 In `golpher.go`, introduce unexported `appConfig` mirroring the public `AppConfig` fields (after the `EnableResponseBodyCapture` rename and `MaxRequestBodyBytes` addition). Make `App` store `config appConfig`, `router *Router`, `errorHandler ErrorHandlerFunc`, `errorObserver ErrorObserverFunc`, `middlewares []MiddlewareFunc`, `lifecycleMu sync.Mutex`, and `frozen atomic.Bool` — all unexported. `New` copies the caller's `AppConfig` into `appConfig`, applies defaults, and stores the private snapshot. Remove exported `App.Config`, `App.Router`, and `App.ErrorHandler` field access. Criterion: external code cannot assign `app.Config`, `app.Router`, or `app.ErrorHandler`; `New(AppConfig{...})` returns an app whose effective config is unaffected by later caller-side mutation.
- [x] 1.2 In `golpher.go`, route every public registration method (`Handle`, verb shorthands, `Use`, `UseHTTP`) through one lifecycle-locked mutation path. Acquire `app.lifecycleMu` once, check `app.frozen` under the mutex, perform the complete mutation through unlocked private helpers, then release; avoid nested locking when a shorthand calls `Handle` or `UseHTTP` composes middleware. Add a fast-path frozen rejection and re-check under the mutex. Criterion: a registration racing with the first `ServeHTTP` either completes before freeze or panics; no deadlock or partial mutation is observable.
- [x] 1.3 In `golpher.go`, `App.ServeHTTP` acquires `app.lifecycleMu`, sets `app.frozen` to true if not already, releases the mutex, then dispatches via the private `router`. Add `App.IsFrozen() bool` returning `app.frozen.Load()`. Criterion: after the first `ServeHTTP` returns, `IsFrozen()` is true and dispatch takes no `lifecycleMu` lock on subsequent requests.
- [x] 1.4 Add focused lifecycle tests in the appropriate internal/external test package covering: caller mutation of a passed `AppConfig` does not change app behavior; `IsFrozen()` is false before first request and true after; registration after first `ServeHTTP` panics; `Use` after freeze panics; concurrent `ServeHTTP` + `Handle` either completes registration before freeze or panics without corruption (`go test -race`). Criterion: tests pass under `-race -shuffle=on`.

## 4. Route validation at registration (LIF-004..LIF-009)

- [x] 4.3 In `router.go`, add structural-conflict detection at the trie position: `:param` vs `*wildcard` at the same position panics; two `:param` with different names at the same position panic (`"golpher: conflicting route: /users/:id vs /users/:name"`); static vs `:param`/`*wildcard` is allowed; same `:param` name is allowed. ## 5. Response integrity: tracking writer, committed/status/bytes (RES-INT-003)

- [x] 5.1 In `response.go`, add fields `status int` (0 = implicit 200), `bytesWritten int64`, `committed bool`, `captureEnabled bool`, `body bytes.Buffer` to `Response`. Rename the chaining setter `Status(code)` to `SetStatus(code) *Response`, migrate all call sites, and add accessors `Committed() bool`, `Status() int`, `BytesWritten() int64`. Criterion: there is no Go method-name collision; staging 201 through `SetStatus` makes `Status()` return 201 and a first implicit write records 200.
- [x] 5.2 In `response.go`, introduce an unexported `trackingResponseWriter` wrapping `http.ResponseWriter` that records `status` and flips `committed` on `WriteHeader`, records implicit 200 on first `Write`, increments `bytesWritten` by the successfully written count, provides `WriteString`/`WriteByte` with safe fallback to `Write`, and implements `Unwrap() http.ResponseWriter`. `Response.Raw()` returns the wrapper; `http.ResponseController(res.Raw())` reaches the real writer for optional operations such as `Flush`/`Hijack`. Criterion: writes through `Raw()` or any `net/http` adapter are counted and tracked, including partial writes and errors.
- [x] 5.3 In `response.go`, route every write helper (`Send`, `String`, `JSON`, `JSONBytes`, `Bytes`, `XML`, `Redirect`) through the tracking writer so `committed`/`status`/`bytesWritten` are updated. Once `committed` is true, repeated `WriteHeader` calls MUST NOT emit a second header on the wire; body writes remain permitted. Criterion: a handler that writes status 200 then returns an error does not produce a second `WriteHeader` on the wire; `BytesWritten()` reflects the body bytes.
- [x] 5.4 In `router.go` `acquireResponse`, accept the `captureEnabled` flag from `app.config` (not a variadic `disableBodyCapture`); construct `Response` with the tracking writer wrapping the underlying `http.ResponseWriter`. Update `releaseResponse` to reset all new fields. Criterion: pooled `Response` values are reset correctly; `acquireResponse` wires the tracking wrapper and capture flag.
- [x] 5.5 Add contract tests: committed status prevents a second `WriteHeader`; bytes count uses successful write counts, including short writes; error rendering does not append after commit; body writes remain possible; `http.ResponseController(res.Raw()).Flush()` reaches an underlying `http.Flusher` and returns an appropriate unsupported error without panic otherwise. Criterion: all assertions pass under `-race`.

Use it for 404, 405, missing QUERY `Content-Type`, and returned body-limit errors as those batches are implemented. Criterion: observer fires once for pre-commit, post-commit, and framework-generated errors; renderer is skipped when committed; nil observer is a no-op.

Criterion: every assertion passes with explicit observer call counts.

Helpers and net/http adapters MUST NOT write a second copy directly into the capture buffer. - [x] 7.2 In `response.go`, replace every direct `header["Content-Type"] = contentTypeHeader(...)` and `header["Content-Length"] = contentLengthHeader(n)` map assignment with `header.Set("Content-Type", ...)` / `header.Set("Content-Length", strconv.Itoa(n))`. Delete the shared package-level `[]string` header vars (`textPlainCharsetUTF8Header`, `applicationJSONHeader`, ...) and the `contentTypeHeader`/`contentLengthHeader` helpers (or convert them to pure string-returning helpers used only to compute the value passed to `Set`). Apply the same change in `error.go` for the default error renderer. Criterion: `grep` for direct `[]string` header aliasing in `response.go`/`error.go` returns zero matches; concurrent requests do not observe each other's header mutations (asserted in tests).
- [x] 7.3 Add contract tests: capture off by default (`BodyString() == ""` and `Body() == nil` after a large write); capture on returns bytes for every helper (`Send`, `String`, `JSON`, `JSONBytes`, `Bytes`, `XML`); an internal test confirms the disabled capture buffer remains empty; a concurrent header test asserts no cross-request contamination. ## 8. Request body safety: lazy MaxBytesReader, Body() returns ([]byte, error), BodyLimit lazy (BODY-001..BODY-005)

- [x] 8.1 In `golpher.go` `appConfig`/`AppConfig`, add `MaxRequestBodyBytes int64`. In `New`, default to `1 << 20` when the field is `0`; keep `0` as "use default", negative as "no limit". Store the effective limit in the private `appConfig`. Criterion: zero-value `AppConfig` yields a 1 MiB effective limit; `MaxRequestBodyBytes: -1` yields no wrapping.
- [x] 8.2 In `request.go`, remove the `*Body` type and its `Bytes()`/`JSON()`/`XML()` methods. Change `Request.Body()` to `func (r *Request) Body() ([]byte, error)`. Add a private `bodyState` on `Request` caching the `([]byte, error)` pair. Add `Request.BodyJSON(v any) error` and `Request.BodyXML(v any) error` that call `Body()` once and decode from cached bytes. Criterion: `req.Body()` returns `([]byte, error)`; repeated calls return the cached pair without re-reading; `errors.As(err, &maxBytesErr)` succeeds when the body exceeds the limit.
- [x] 8.3 In `request.go` and `router.go`, replace the removed `ctx` field with a private `response *Response` reference on `Request`; set it in `acquireRequest(req, response, ...)` and clear it in `releaseRequest`. Add an idempotent first-access helper that calls `http.MaxBytesReader(r.response.Raw(), r.http.Body, effectiveLimit)` only for positive limits and never reads eagerly. Decoders, `Body()`, and net/http adapters call it before reading. Ensure returned errors that are or wrap `*http.MaxBytesError` render as 413 while the observer receives the original error. Criterion: no nil response reaches normal dispatch body reads; pooled requests clear the reference; chunked/unknown-length overflow is bounded.
- [x] 8.4 In `middleware.go`, rewrite `BodyLimit` as a lazy override: it updates the per-request effective limit (stored on `Request`) before first read; it does not read or wrap the body itself. Negative override disables the app limit for that route; zero override means "use app default"; positive override enforces that many bytes. Criterion: `BodyLimit(64*1024)` over an app limit of 1 MiB enforces 64 KiB; `BodyLimit(-1)` disables the limit; `BodyLimit(0)` keeps the app limit; no eager read occurs.
- [x] 8.5 Add regression/contract tests: default limit is 1 MiB; `0` = default; negative = unlimited; custom positive limit enforced; a counting `io.ReadCloser` proves that an unused body receives zero reads; `Body()` caches result and error; `*http.MaxBytesError` propagates through `errors.As` for `Body()` and decoders; returning that error renders 413; unread body remains intact across middleware. Criterion: all cases pass under `-race -shuffle=on`.
- [x] 8.6 Add a concurrent `-race` test for a route-level `BodyLimit` override with requests both below and above the limit. Criterion: each request observes its own limit and no request state leaks through pooling.

## 9. HTTP QUERY method: constant, registration, dispatch, Allow, Content-Type 400 (QUERY-001..QUERY-007)

- [x] 9.1 In `golpher.go` (or a new `methods.go`), add `const MethodQuery = "QUERY"` with a doc comment referencing RFC 10008 and stating `QUERY` is safe and idempotent. Criterion: `golpher.MethodQuery` equals `"QUERY"`.
- [x] 9.2 In `golpher.go`, add `App.QUERY(pattern string, handler HandlerFunc, middlewares ...MiddlewareFunc)` delegating to `Handle(MethodQuery, ...)`. In `group.go`, add `Group.QUERY(...)` with the same signature and prefix handling. Criterion: `app.QUERY("/q", h)` registers a route with method `"QUERY"`; `group.QUERY("/q", h)` with prefix `/api` registers `/api/q` for `"QUERY"`.
- [x] 9.3 In `router.go`, ensure `QUERY` is treated as a first-class method in static index, dynamic trie, and `allowedMethods`/`Allow` generation. No method allowlist blocks it (D8 validator accepts the RFC 9110 token). Criterion: a `QUERY` request to a registered `QUERY` route dispatches; `Allow` on a method mismatch includes `QUERY`; a `QUERY`-only path returns `405` with `Allow: QUERY` for a `GET` request.
- [x] 9.4 In the dispatch path, before invoking a `QUERY` handler, reject a request whose `Content-Type` header is absent with `400 Bad Request`. Do not reject solely on `Content-Length: 0` — empty content with a declared media type is dispatched to the handler/decoder. The body limit (batch 8) applies to `QUERY` bodies (`413` on overflow). The framework does not auto-emit `415` or `Accept-Query`; handlers own media-type negotiation per QUERY-006. Criterion: `QUERY` without `Content-Type` → `400`; `QUERY` with `Content-Type` and empty body → dispatched to handler; `QUERY` body > limit → `413`.
- [x] 9.5 Add contract tests: `MethodQuery`; `App.QUERY`/`Group.QUERY`; static/dynamic matching; `Allow`; missing `Content-Type` → 400; declared media type with empty content reaches handler; fixed-length and chunked QUERY bodies over the limit → 413 when read/returned; URI query parameters remain distinct. Criterion: all assertions pass under `-race -shuffle=on`.
